# Дизайн-система: сборщик

Собирает браузерный кит визуальной системы из **настоящих исходников
проекта** — `apps/game/src/ui/tokens.css`, `Icon.tsx`, сгенерированных SVG.
Ничего не пишется руками: кит, написанный руками, расходится с игрой на
первой же правке и превращается в красивую ложь.

Правила системы — в [`docs/DESIGN.md`](../../docs/DESIGN.md). Здесь только
сборка их браузерного представления.

## Запуск

```bash
node tools/design-system/build.mjs          # в tools/design-system/out/project
DS_OUT=/куда/угодно node tools/design-system/build.mjs
```

## Устройство

`parts/*.mjs` выполняются по порядку имён и **перезаписывают** файлы друг
друга — последняя правда за последней частью, поэтому бренд-книга собирается
в самом конце.

| Часть | Что собирает |
|---|---|
| `01-foundation` | токены, закон трёх слоёв, кнопки, глифы, плашки, угрозы, цель, герой, порода, обложка |
| `02-hud-light-props` | иконки HUD, свет, декор, карточка испытания дня |
| `03-motion-and-tokens` | движение с живыми демо, затемнения, разграничение глифов и иконок |
| `04-brandbook` | `README.md` — бренд-книга целиком |

`glyphs.json` — выгрузка `GLYPHS` из `src/ui/Icon.tsx`. Пересобрать после
правки глифов:

```bash
node -e "const fs=require('fs');const s=fs.readFileSync('apps/game/src/ui/Icon.tsx','utf8');\
const b=s.slice(s.indexOf('export const GLYPHS = {'),s.indexOf('} satisfies Record'));\
fs.writeFileSync('tools/design-system/glyphs.json',JSON.stringify(eval('({'+b.slice(b.indexOf('{')+1)+'})'.replace(/\/\*\*[\s\S]*?\*\//g,'')),null,1))"
```

## Публикация

Кит живёт артефактом типа Design System. Обновление: собрать, скопировать
дерево `project/` внутрь рабочей директории и опубликовать по ссылке
артефакта — инструмент публикации не принимает пути вне рабочей директории.

Индекс `project/design-system.json` пишется **последним** и только после
перечитывания текущего: иначе правка, сделанная в браузере, затрётся.
